# Quarantined chain snapshots

Files in this directory were generated by the chain recorder while it was
running on **non-trading days** (weekends / NSE holidays). NSE is closed on
those days, so the underlying data came from the in-process **simulator**,
not the live exchange.

These files are kept (not deleted) so we can:
  1. Forensically inspect what the simulator produced.
  2. Cross-check that the new weekday/holiday gate in the recorder really
     prevents new contamination from accumulating here.

**Do not feed these into the replay engine.** The replay engine assumes the
chain CSV reflects real exchange ticks — replaying simulator output would
silently leak fake P&L back into "real chain replay" results.

## Why these were quarantined (Apr 17 audit)

| File | Weekday | Reason |
|------|---------|--------|
| `chain_2026-03-28.csv` | Saturday | NSE closed |
| `chain_2026-03-29.csv` | Sunday   | NSE closed |
| `chain_2026-04-04.csv` | Saturday | NSE closed |
| `chain_2026-04-05.csv` | Sunday   | NSE closed |
| `chain_2026-04-11.csv` | Saturday | NSE closed |
| `chain_2026-04-12.csv` | Sunday   | NSE closed |

The fix that prevents new files like these landing here:
`src/market_data/chain_recorder.py::_record_loop` now calls
`MarketClock.is_trading_holiday()` before every snapshot.
